# 🔐 QRNode

**QRNode** is a lightweight local web application for creating and reading secure, encrypted QR codes.

It converts text into an encrypted QR format called **YQR**, supports large messages across multiple QR symbols, and combines them into a single PNG image.

QRNode is designed to run locally on **Android/Termux** as well as standard Python environments.

---

## ✨ Features

- 🔐 AES-256-GCM encryption
- 🛡️ HMAC-SHA256 integrity verification
- 📦 Automatic multi-part QR support
- 🖼️ Multiple QR codes combined into one PNG
- ⚡ Fast QR decoding using ZXing-C++
- 🔑 Local secret key
- 🧩 Custom YQR data format
- 📱 Browser-based interface
- 🌐 Local Flask server
- 💾 Generated PNG images are kept temporarily in memory
- 🚫 No permanent generated-image storage
- 🔍 Only QR payloads generated by QRNode are accepted
- 📏 Supports large text by automatically splitting it across QR codes
- 📱 Works on Android through Termux

📥 Installation
1. Clone the repository
git clone https://github.com/yonukwasim520-cyber/QRNode.git
cd QRNode
2. Install Python dependencies
pip install flask segno pillow pycryptodome
🔧 ZXing-C++ Setup
QRNode uses ZXing-C++ for QR decoding.
Clone the repository:
git clone --depth 1 --recursive https://github.com/zxing-cpp/zxing-cpp.git ~/zxing-build
Create the build directory:
cd ~/zxing-build
cmake -S . -B build \
  -DZXING_C_API=ON \
  -DBUILD_SHARED_LIBS=ON
Build ZXing-C++:
cmake --build build -j2
🧩 Build the QRNode ZXing Library
Return to QRNode:
cd ~/QRNode
Compile the native QR decoder:
clang++ -std=c++17 -fPIC -shared \
  -I$HOME/zxing-build/core/src \
  -I$HOME/zxing-build/build/core \
  yqr_zxing.cpp \
  -L$HOME/zxing-build/build/core \
  -lZXing \
  -Wl,-rpath,$HOME/zxing-build/build/core \
  -o yqr_zxing.so
Verify that the library exists:
ls -lh yqr_zxing.so
🔑 Secret Key
QRNode requires a local encryption key stored in:
secret.key
Generate a new 32-byte AES key:
python -c "import secrets; open('secret.key','wb').write(secrets.token_bytes(32))"
Verify it:
ls -lh secret.key
⚠️ Important
Never upload secret.key to GitHub.
The .gitignore file should contain:
secret.key
Anyone who has your secret.key can potentially decrypt QR data created with that key.

📝 Creating an Encrypted QR
Enter your text.
Press Create Image.
QRNode encrypts the data.
If the encrypted payload is small enough, one QR code is generated.
Larger payloads are automatically divided into multiple QR parts.
The QR parts are combined into one PNG image.
The generated image can be downloaded.
🔍 Reading a QRNode Image
Select a QRNode-generated PNG.
Press Read.
QRNode detects the embedded QR symbols.
The individual parts are reconstructed.
HMAC-SHA256 is verified.
AES-GCM authentication and decryption are performed.
The original text is displayed.
🔐 Security
QRNode uses several layers of protection.
AES-GCM
The original text is encrypted using AES-GCM before being placed inside the QR code.
The encrypted payload contains:
nonce + ciphertext + authentication tag
HMAC-SHA256
QRNode generates an HMAC signature for the complete encrypted payload.
This allows the application to detect modified or corrupted QR data.
The signature is truncated to 24 hexadecimal bytes/characters as implemented by the application.
📦 YQR Format
QRNode uses a custom format:
YQR1|G=<group_id>|P=<position>|T=<total>|D=<chunk>|S=<signature>
Example:
YQR1|G=abc123|P=1|T=3|D=...|S=...
Where:
Field
Description
YQR1
YQR format identifier
G
Unique QR group ID
P
Current part number
T
Total number of parts
D
Encrypted payload chunk
S
HMAC signature
📦 Multi-Part QR
Large data is automatically divided into multiple QR codes.
For example:
Part 1 / 5
Part 2 / 5
Part 3 / 5
Part 4 / 5
Part 5 / 5
The user receives one PNG image containing all QR symbols.
QRNode stores the exact QR positions in the PNG metadata so the reader can efficiently extract each QR region.
🖼️ Image Storage
Generated QR images are not permanently written to the project's exports/ directory.
QRNode temporarily stores generated PNG data in memory.
The temporary image is automatically removed after the configured expiration period.
This helps prevent the project directory from filling up with generated QR images.
